# Agentic Slicer: REST and MCP on one backend

The owner approved REST implementation and documentation publication on 2026-10-15. Keep the standalone repository `MoraesGil/snapmaker-orca-mcp`; “Agentic Slicer” describes its agent-facing workflow. The separate local installation directory contains runtime/data, not another codebase. The former full Orca fork is retired.

## Contract

- Version the new package as 0.4.0. Keep the official native engine at `9bf2f18eaff7cc0655cbdeef6a215660085ecb0f`; preserve executable/resources, read-only inputs/presets, all 33 MCP tools, three resource templates, default stdio and the existing `/mcp` URL.
- The existing Starlette application serves REST and MCP under the same bearer/Host/Origin policy. REST receives the exact same `Slicer` instance as MCP, including its native-execution lock and verified artifact cache. No second listener, worker process, container, engine installation or loopback HTTP call inside MCP.
- `POST /api/v1/slices` accepts strict JSON `input_3mf`, nonnegative integer `plate` (default0), boolean `force` (defaultfalse), boolean `allow_newer_file` (defaulttrue). It waits for the completed result and returns200 with the existing native manifest plus relative artifact links. This release does not claim asynchronous202 submission or queued-job progress. Clients must configure a timeout longer than the native timeout and possible queue wait; client disconnection is not a native cancellation request.
- `GET /api/v1/jobs/{job_id}` returns a retained completed manifest. `GET .../props`, `GET .../source`, `GET .../plates/{plate}/gcode` and `GET .../plates/{plate}/lines?start=1&count=200` expose verified artifacts and bounded line ranges (1..1000). Job IDs are32 lowercasehex, plate IDs are positive integers; paths never come from user-supplied download filenames or stored absolute result paths. Corrupt/missing artifacts fail explicitly; no download cache may bypass integrity checks. Downloads include content hashes as ETags and private/no-store policy.
- `GET /api/v1/engine` reports local bound identity; `GET /api/v1/openapi.json` describes the shipped REST contract and requires authentication. `/health` remains minimal and public under its existing Host/Origin constraints.
- Malformed JSON400, invalid schema422, absent input/job/plate404, unsupported project400, corrupt artifact or engine identity conflict409, native process failure502, native timeout504. Native failures retain diagnostic paths; errors must not log authentication headers or silently substitute another motor/GUI.
- Public docs explain the single repository, optional app integration, REST request duration, GUI compatibility versus automatic computer-use fallback, no bundled skill, and the concrete selective-query/bounded-output workflow. Token reduction is an unmeasured motivation, not a percentage or guaranteed total-token claim. ForjaFarm can manage ready G-code without a slicer; preparation from 3MF is an optional integration and remains outside its codebase in this task.

## Acceptance

REST output downloads, source/props integrity, malformed input, protected routes, errors, bounded output and shared REST/MCP cache must pass through real ASGI/MCP transports with a process double at the native boundary. A blocked native REST call must leave MCP reads and health available. Installed acceptance uses the unchanged official runtime, one persistent container and both protocols, preserving source/preset hashes. Run the public suite, review the change independently, publish main/release and update the local deployment/runbook/tooling only after validation. No printer action or physical/GUI-equivalence certification.
